# NS Shipping Converter

쿠팡·네이버 스마트스토어·토스쇼핑 주문 Excel을 한 페이지에서 분석하고 롯데택배 송장 등록용 Excel로 변환하는 업무용 웹 앱입니다. Next.js App Router, TypeScript strict, React, Tailwind CSS, shadcn/ui 패턴의 Radix 컴포넌트, Lucide, ExcelJS를 사용합니다.

## 실행

Node.js 22 이상을 권장합니다.

```bash
npm ci
npm run dev
```

브라우저에서 http://127.0.0.1:3000 을 엽니다. 운영 빌드는 `npm run build`, 실행은 `npm start`입니다. 현재 실행 환경의 Turbopack 내부 포트 제한을 피하기 위해 운영 빌드는 Next.js가 지원하는 Webpack을 사용합니다. 파일 처리에 백엔드·DB·로그인은 필요하지 않습니다. 폰트·분석 SDK 등 외부 요청도 사용하지 않습니다.

## 사용 흐름

1. `.xlsx` 주문 파일 여러 개를 클릭하거나 끌어놓습니다. 파일당 20MB, 시트당 50,000행·500열까지 허용합니다.
2. 파일별 인식 결과, 주문 건수, 정상·확인 필요·오류, 마켓별 건수를 확인합니다.
3. 상태 탭과 검색으로 주문을 찾습니다. 주문번호·전체 내용·수정 아이콘을 클릭하면 필수값과 원본 시트/행을 확인하고 수정할 수 있습니다.
4. 중복은 자동 삭제하지 않습니다. 포함 체크를 해제하면 출력에서 제외됩니다. 오류는 체크 여부와 관계없이 출력에서 제외되고, 수정되면 다시 포함할 수 있습니다. 옵션·배송메시지 누락 등의 경고는 출력 가능합니다.
5. 발송인 이름·전화·운임과 선택 전화·주소·우편번호를 설정합니다. 기본 발송인은 엔에스벨류몰, 운임은 신용입니다. 전화번호는 사용자가 입력해야 합니다.
6. 상품명 규칙은 **완전 일치**로 치환합니다. 미리보기와 출력에 즉시 적용하며 원본 주문명은 보존합니다.
7. 롯데택배 엑셀 다운로드를 누릅니다. 한국 시간 기준 파일명으로 단일 `Sheet1`, 원본과 동일한 18열을 생성합니다. 운임과 운송장번호는 비워둡니다.
8. 새 작업으로 주문만 지울 수 있습니다. 설정은 유지됩니다.

## 실제 샘플 및 지원 구조

`samples/`에 제공된 실제 파일이 있습니다. [분석 기록](docs/sample-analysis.md)에 관찰한 구조를 기록했습니다.

| 마켓         | 실제 시트    | 헤더 / 첫 데이터 | 샘플 주문 |
| ------------ | ------------ | ---------------- | --------- |
| 쿠팡         | Delivery     | 1 / 2행          | 3건       |
| 스마트스토어 | 발주발송관리 | 2 / 3행          | 5건       |
| 토스쇼핑     | 주문내역     | 2 / 4행          | 2건       |

시트 이름이나 파일명만으로 추정하지 않고 처음 30행의 실제 헤더를 검사합니다. 토스의 수정 안내 행은 내용으로 구분하므로 안내 행이 삭제되어도 첫 주문을 잃지 않습니다. 한 파일에 여러 지원 시트가 있으면 모두 읽고, 미인식 시트가 있으면 사용자에게 표시합니다. 스마트스토어는 통합배송지 우선, 빈 경우 기본배송지와 상세배송지를 결합합니다.

## Excel 변환 구조

```text
src/types/order.ts                          공통 주문·발송인·규칙·오류 타입
src/lib/excel/reader.ts                     브라우저 파일 읽기 / 파일 오류
src/lib/excel/detectPlatform.ts             헤더 감지와 adapter 등록
src/lib/excel/parsers/{coupang,smartstore,toss}.ts
src/lib/excel/parsers/shared.ts             공통 모델 정규화 / 원본 행 추적
src/lib/excel/validators/orderValidator.ts  검증 / 중복 식별
src/lib/excel/transforms/                   전화번호 보존 / 상품명 치환
src/lib/excel/exporters/lotte.ts            원본 양식 기반 출력
src/lib/excel/exporters/template-schema.json 원본에서 추출한 비개인 서식
src/components/                            업로드 / 표 / 수정 / 설정 UI
```

파서와 exporter는 분리되어 있습니다. identifier, 전화번호, 우편번호는 문자열로 유지하며 Excel 출력에도 텍스트 타입과 `@` 서식을 씁니다. 수량만 정수입니다. 원본에서 숫자로 저장된 16자리 이상 주문번호는 이미 손상되었을 수 있으므로 복원한 척하지 않고 오류로 표시합니다. 수식 셀도 직접 확인 전 출력되지 않습니다. 특이한 전화번호는 삭제·임의 변환하지 않습니다. 국내 우편번호가 1~4자리 숫자이면 5자리로 0을 채웁니다.

롯데 원본 헤더 서식, 열 너비, 헤더 높이, 데이터 기본 서식을 재사용합니다. 템플릿을 바꿀 때는 실제 파일 확인 후 `node scripts/extract-template.mjs`로 서식 메타데이터를 갱신합니다. 해당 스크립트는 헤더와 서식만 추출합니다. 양식에는 불필요한 시트·데이터·수식을 추가하지 않습니다.

## 테스트

```bash
python3 scripts/extract-expected.py
npm test
npm run lint
npm run build
# 별도 터미널에서 npm start 또는 npm run dev 실행 후
npm run test:e2e
```

단위/통합 테스트는 실제 세 샘플 모든 행을 독립 OOXML 추출값과 비교하고, 각 마켓 및 통합 롯데 파일 생성 후 다시 읽어 원본 18열, 값, 문자열, 앞자리 0, 서식, 빈 운임/운송장번호를 확인합니다. 추가로 빈 필수값, 수량 오류, 중복, 안내 행 삭제, 주소 대체, 수식, 정밀도 위험, 상품명 규칙, 암호화·손상·미지원 파일을 검증합니다.

Playwright 테스트는 시스템 Google Chrome을 사용합니다. 다중 업로드, 오류 수정, 상품명 치환, 설정 유지, 실제 다운로드, 중복 제외, 초기화, 오류 안내, 모바일 가로 넘침, 주문 업로드 POST 부재를 검사합니다. 검증 결과물은 Git에서 제외된 `outputs/verification/`에 저장됩니다. 실패 추적에는 주문정보가 담길 수 있으므로 `test-results/`도 비공개로 관리합니다.

## 새 마켓 추가

1. 실제 주문 샘플을 먼저 분석합니다.
2. `Platform`과 한국어 레이블을 확장합니다.
3. `parsers/`에 `Adapter`를 추가하고 확인한 식별 헤더·필드 매핑·안내행 규칙을 정의합니다.
4. `detectPlatform.ts`의 adapter 목록에 등록하고 UI 마켓 표시를 확장합니다.
5. 실제 샘플과 독립 기대값으로 감지·파싱·출력 회귀 테스트를 추가합니다.

기존 플랫폼 파서를 수정할 필요가 없으며, 롯데 exporter는 공통 주문 모델만 받습니다.

## 개인정보 처리

파일의 `arrayBuffer()`를 브라우저 ExcelJS가 직접 읽습니다. 파일 업로드 API, 서버 저장, DB, 로그인, 분석 SDK가 없습니다. 주문 목록은 React 메모리에만 존재하고 페이지 새로고침/닫기/새 작업으로 사라집니다. `localStorage`에는 사용자가 설정한 발송인(전화·주소 포함), 상품명 치환 규칙, Excel 비밀번호를 저장합니다. 공유 PC에서는 브라우저 사이트 데이터를 삭제해 설정을 지울 수 있습니다. 샘플·테스트 기대값·검증 파일은 Git과 공개 정적 파일에서 제외됩니다.

## 확인 범위

실제 10건의 데이터 보존과 Excel 구조, 앱의 다운로드 흐름을 자동 검증합니다. 롯데택배의 실제 운영 프로그램에 파일을 제출하는 작업은 수행하지 않았습니다. 제공된 양식의 구조와 서식을 기준으로 출력하며, 운영 프로그램의 등록 성공 여부는 해당 프로그램에서 최종 확인할 수 있습니다. 암호화 Excel은 브라우저 Web Worker에서 해제합니다. 사용자 요청에 따라 기본 비밀번호는 `0000`이며, 설정의 Excel 비밀번호에서 변경하면 이 브라우저에서 다음 방문에도 유지됩니다. 암호 파일 원본은 변경하지 않습니다. 잘못된 비밀번호 또는 지원하지 않는 형식은 오류로 표시합니다.

## 스마트스토어 암호 파일

`samples/smartstore-encrypted.xlsx`는 추가 제공된 전체주문 20260929_2213 원본으로, 실제 데이터 1건을 포함합니다. 비밀번호 `0000`으로 열기, 주문 파싱, 롯데 출력 재읽기를 검증합니다. `predev`와 `prebuild`에서 복호화 워커를 로컬 번들링합니다. 워커는 암호 파일을 올렸을 때만 로드하며 외부 CDN을 사용하지 않습니다. 공개 배포 전에 개인 업무용 기본 비밀번호 정책을 변경할 수 있습니다.

## 쿠팡 품명 매핑

사용자 지정에 따라 쿠팡 샘플 L열 `등록옵션명`의 내용을 롯데택배 `상품명1`로 출력합니다. 예: `코지 베이지 무릎담요(100x150)`. 열 위치가 바뀌어도 확인된 헤더 이름으로 찾습니다. 기존 상품상세1 매핑과 다른 마켓의 매핑은 유지됩니다. 상품명 치환 규칙을 별도로 설정했다면 이 품명에 적용됩니다.
