# NS Shipping Converter 개선 요청: 개인정보 안내와 사용 가이드

## 목표

현재 공개된 `https://nshome.life` 서비스를 무료로 유지하면서, 처음 방문한 사람이 개인정보 처리 방식을 쉽게 이해하고 마켓 주문 엑셀 변환 방법을 검색으로 찾을 수 있도록 개선한다.

## 반드시 지킬 점

- 쿠팡·스마트스토어·토스 엑셀의 구조와 기존 동작은 실제 샘플 분석 결과 및 현재 코드의 Source of Truth를 따른다. 컬럼·행 구조를 추측해 문서화하지 않는다.
- 주문 파일을 서버에 업로드하거나 저장하는 기능은 추가하지 않는다. 분석과 변환은 브라우저에서 계속 수행한다.
- 실제 주문자 이름, 전화번호, 주소, 우편번호, 주문번호, 원본 파일을 문구·문서·테스트 데이터에 복사하지 않는다.
- 기능과 디자인을 임의로 축소하지 않는다. 기존 변환·검증·편집·다운로드 흐름을 보존한다.
- 기존 롯데택배 출력 엑셀의 헤더명, 헤더 순서, 열 개수, 열 위치, 시트 구성, 양식 파일 구조와 서식을 변경하지 않는다. 가이드·SEO·개인정보 안내 작업은 출력 엑셀 양식에 영향을 주지 않아야 한다.
- 기존 마켓별 입력 엑셀 헤더 감지와 필드 매핑도 그대로 유지한다. 새로운 요구가 이 동작이나 출력 헤더를 바꾸게 된다면, 해당 변경은 이번 범위에 포함하지 말고 별도 요청으로 다룬다.
- 확인되지 않은 마켓 정책이나 택배사 규칙을 단정하지 않는다.
- 정보성 안내 페이지 제작이며, 유료 기능·광고·회원가입·로그인 요구는 추가하지 않는다.

## 1. 첫 화면의 개인정보 안내

파일을 선택하기 전부터 보이는 위치에 다음 내용을 짧고 읽기 쉽게 표시한다. 모바일에서도 잘리지 않아야 한다.

> 엑셀 파일은 브라우저에서 처리되며, 주문 파일을 서버로 전송하거나 저장하지 않습니다.

문구는 실제 코드와 대조해 검증한다. 주문 데이터가 브라우저 메모리에서 처리되고 업로드 API나 주문 DB가 없다는 사실을 확인한다. 발송인 정보, 상품명 치환 규칙, 엑셀 비밀번호 설정은 편의를 위해 브라우저 `localStorage`에 저장될 수 있으므로 주문 파일 처리와 구분해 설명한다. 공용 컴퓨터에서 브라우저 프로필을 분리하거나 사용 후 사이트 데이터를 지우는 안내를 덧붙인다.

정적 웹사이트 접속 과정에서 호스팅 환경이 일반 접속 정보를 처리할 수 있으므로, “어떤 정보도 어디에도 전송되지 않는다”처럼 범위를 과장하지 않는다. 이 안내만으로 개인정보 처리방침 등 법적 문서를 대체한다고 표현하지 않는다.

## 2. 마켓 엑셀 사용 안내 페이지

아래 네 주제의 한국어 페이지를 만든다.

1. 스마트스토어 주문 엑셀을 롯데택배 양식으로 변환하는 방법
2. 쿠팡 주문 엑셀의 상품명·옵션명과 롯데택배 출력 내용을 확인하는 방법
3. 비밀번호가 설정된 주문 엑셀을 여는 방법
4. 변환 오류·누락 주문·중복 주문을 확인하고 처리하는 방법

각 페이지에는 다음 내용을 포함한다.

- 구체적인 문제를 설명하는 제목과 첫 문단
- 실제 앱 버튼·메뉴 이름을 사용한 단계별 절차
- 확인된 경우에 한해 입력 필드와 롯데택배 출력 항목의 매핑
- 오류가 발생했을 때 확인할 내용과 데이터 손실을 피하는 방법
- 브라우저 처리 안내 및 개인정보 설명 페이지 링크
- 변환 화면으로 이동하는 링크
- 휴대전화에서도 따라 하기 쉬운 구성

기존 확인 사항은 구현 직전에 현행 코드와 문서로 다시 확인한다. 스마트스토어 상품명·옵션명은 원본 필드를 각각 사용하며 임의 분리하지 않는다. 쿠팡의 확인된 `등록옵션명`은 롯데택배 `상품명1`로 출력된다. 암호 파일 기본 비밀번호는 사용자 요청에 따라 `0000`이며 설정에서 변경할 수 있다. 실제 동작이 달라졌다면 현재 구현에 맞춘다.

가이드마다 독립적인 문제 해결 정보를 제공한다. 실제 샘플의 데이터는 게시하지 않으며, 필요한 예시는 중립적인 값으로 만든다.

## 검색 기본 설정

- 각 페이지에 고유한 `<title>`, 검색 결과 설명(description), 명확한 H1을 작성한다.
- 첫 화면 제목은 기능을 한국어로 간결하게 표현한다. 예: “쿠팡·스마트스토어 주문 엑셀을 롯데택배 양식으로 변환”.
- 정적 배포 환경에서 검색 로봇이 페이지 HTML과 링크를 읽을 수 있는지 확인한다.
- 공개 가이드 URL을 포함하는 `sitemap.xml`을 제공하고 robots 설정이 크롤링을 막지 않는지 확인한다.
- Search Console·네이버 서치어드바이저 등록 방법을 안내할 수 있다. 소유권 인증이 필요한 외부 계정에 사용자 자격증명을 요구하거나 대신 입력하지 않는다.
- 검색어를 부자연스럽게 반복하거나 사실과 다른 구조화 데이터를 넣지 않는다. 구조화 데이터는 실제 페이지에 표시되는 정보와 일치할 때만 쓴다.

## 디자인과 사용성

- 기존 앱의 색상, 글꼴, 버튼과 간격 체계를 따른다.
- 개인정보 안내는 눈에 띄게 표시하되 파일 선택·변환 버튼을 가리지 않는다.
- 변환 도구와 가이드 사이에 찾기 쉬운 내비게이션이나 링크를 제공한다.
- 모바일 가독성과 키보드 접근성을 유지한다.
- 광고·팝업·자동 다운로드는 추가하지 않는다.

## 검증 및 완료 조건

- 첫 화면과 새 가이드가 데스크톱·모바일에서 잘 읽힌다.
- 모든 가이드 링크와 변환 도구 링크가 정상 이동한다.
- 각 페이지의 제목·설명·H1이 목적에 맞고 서로 구분된다.
- 사이트맵에는 공개 페이지만 포함하며 주문 데이터·샘플·개인 설정은 포함되지 않는다.
- 검색 로봇 접근을 로그인이나 `noindex`로 막지 않는다.
- 기존 변환 기능과 공개 배포 방식을 보존하고 프로젝트 필수 검사를 통과한다.
- 기존 롯데택배 출력 파일의 18개 헤더 값과 순서, 한 시트 구성, 기존 열 너비·서식을 기준 샘플과 대조해 바뀌지 않았음을 확인한다.
- 주문 데이터가 네트워크 요청 본문으로 전송되지 않는 보장도 유지한다.
- 마무리 보고에 변경 파일, 주요 결정, 검사 결과, 배포 여부를 적는다.
